Common Pitfalls & Troubleshooting

= instead of ==

# !! one = means "assign" or "name an argument", not "is equal to"
flights |>
  filter(month = 1)
Error in `filter()`:
! We detected a named input.
ℹ This usually means that you've used `=` instead of `==`.
ℹ Did you mean `month == 1`?

dplyr catches this and suggests the fix:

flights |>
  filter(month == 1) |>
  count(month)
# A tibble: 1 × 2
  month     n
  <int> <int>
1     1 27004

Forgetting na.rm = TRUE

# !! any missing value makes the whole result NA
flights |>
  summarize(avg_delay = mean(arr_delay))
# A tibble: 1 × 1
  avg_delay
      <dbl>
1        NA
# Fix: ignore missing values
flights |>
  summarize(avg_delay = mean(arr_delay, na.rm = TRUE))
# A tibble: 1 × 1
  avg_delay
      <dbl>
1      6.90

Using the & and | Operators

# Keep only flights in January OR February
# !! PRODUCES A BUGGED OUTPUT
flights |>
  filter(month == 1 | 2) |>
  count(month)
# A tibble: 12 × 2
   month     n
   <int> <int>
 1     1 27004
 2     2 24951
 3     3 28834
 4     4 28330
 5     5 28796
 6     6 28243
 7     7 29425
 8     8 29327
 9     9 27574
10    10 28889
11    11 27268
12    12 28135

Error: R treats nonzero numbers in conditional statements as TRUE, so it reads this as “keep rows where month is 1, or TRUE”, which keeps every row.

# Fix 1
flights |>
  filter(month == 1 | month == 2) |>
  count(month)
# A tibble: 2 × 2
  month     n
  <int> <int>
1     1 27004
2     2 24951
# Fix 2
flights |>
  filter(month %in% c(1, 2)) |>
  count(month)
# A tibble: 2 × 2
  month     n
  <int> <int>
1     1 27004
2     2 24951

Forgetting to Save with <-

flights |>
  filter(month == 1) |>
  nrow()
[1] 27004
nrow(flights) # unchanged!
[1] 336776

dplyr verbs never change the original data. To keep the result, save it: jan_flights <- flights |> filter(month == 1).

Quoting Column Names in Pivots

wide <- tibble(id = 1:2, `2022` = c(5, 6), `2023` = c(7, 8))

# !! names_to without quotes: R looks for an object called year (and finds lubridate's year() function)
wide |>
  pivot_longer(cols = -id, names_to = year, values_to = "n")
Error in `pivot_longer()`:
! `names_to` must be a character vector or `NULL`, not a function.
# Fix: new column names are quoted
wide |>
  pivot_longer(cols = -id, names_to = "year", values_to = "n")
# A tibble: 4 × 3
     id year      n
  <int> <chr> <dbl>
1     1 2022      5
2     1 2023      7
3     2 2022      6
4     2 2023      8

Joins That Add Rows

!! A one-to-many join repeats rows on the “one” side. A total or average taken after the join can double count:

counties <- tibble(county_id = c(101, 103), population = c(10000, 15000))
programs <- tibble(county_id = c(101, 101, 103), program = c("A", "B", "C"))

# Real total population is 25,000, but Alder is counted twice
counties |>
  left_join(programs, by = "county_id") |>
  summarize(total_pop = sum(population))
# A tibble: 1 × 1
  total_pop
      <dbl>
1     35000

Fix: summarize the “many” table first (e.g. count(county_id)), then join. Or add relationship = "one-to-one" to make dplyr error when there are duplicates.

NA Is Not Zero

After a left_join(), unmatched rows get NA. That means unknown, not 0. Don’t replace them with 0 unless you know the true value is zero.
